## Implementation scope

The source composition, photography, type, page content, API and submission IDs were preserved. That motion patch corrected interaction lifecycle and compositing:

- The residences scene pins at `bottom bottom` when its source composition is taller than the viewport, so the lower description is readable before the mask opens. Taller windows retain `top top`.
- Breakpoint changes do not replay already revealed text. Scroll-linked artwork settles with 0.6 s scrub, and fonts/load/pageshow refreshes are coalesced.
- Permanent `will-change` reservations were removed from the oversized masked sunset/architecture layers.
- The interior gallery decodes the requested image before crossfading over the previous opaque image. Rapid inputs keep only the last request. Hidden slides are inert; vertical scrolling and taps remain native, while horizontal swipe is captured and does not open the lightbox.
- Plan zoom preserves the visual center when the image is smaller than the viewport. The image remains centered at intermediate zoom; viewport resize returns to fit. Toolbar controls correctly disable at their zoom bounds.
- Dialog opening has a short transform/opacity entrance, reduced-motion gets no animation, and stable scrollbar space avoids layout shifts during scroll lock.

## Additional browser scenarios

This checklist remains a manual guide; not every gesture, viewport or delayed-request case below is automated by the existing suite.

1. At 1440 x 900 with normal motion, scroll through the residences intro slowly and in one fast wheel burst. Its heading and lower description must be readable, the silhouette should open smoothly, and the catalogue should follow without blank pin space or overlap. Reverse through the scene.
2. Repeat at 1440 x 650 and 1920 x 1080. A tall intro must reach its lower edge before pinning. Resize to 390 x 844 while inside the intro, then back to desktop. Mobile must have no pinned spacer and all text must remain visible.
3. Visit `/#plans` directly with normal motion, then open Unit 3402 and return with browser Back. The restored anchor, filter state, and visible text must survive font completion and bfcache restoration.
4. In the interior gallery, rapidly click Next three times, use Left/Right, then swipe on a touch viewport. The counter and visible image must agree; no cream frame should appear mid-transition. A vertical swipe must scroll the page; a tap on the image must still open the full-screen viewer.
5. Delay the next gallery image request. The old image must remain visible until decode; clicking Previous while loading must win. Simulate a failed image request and verify the current image remains usable.
6. Open the Unit 3402 plan, zoom to 150%, 400%, pan, and fit. On a wide viewer the smaller plan must stay centered. Rotate/resize the viewport while zoomed; the plan should return to fit, with working controls and no stale drag. Close and reopen.
7. Open and close each dialog at desktop and mobile widths. Page content must not shift horizontally. Escape restores focus to the visible trigger. Repeat after setting reduced motion while an animation is active.

## Regression harness correction

Document width is checked as scrollWidth/body scrollWidth <= the root clientWidth plus one rounding pixel. A stable scrollbar gutter may make a 1440 viewport's usable document 1425 pixels wide, which is not overflow. Fixed viewport-width equality was removed.

The normal-motion flow now checks readability before pinning in a short desktop window, live resize to mobile with pin cleanup and non-overlapping copy, keyboard gallery/inert state and a reduced-motion change during transition. Counter waits follow decoded selection instead of assuming synchronous clicks. Node syntax validation and diff checks passed, followed by the successful final server browser job `20261101T124919-e3044c77a5`; the earlier rerun requirement is complete.

## Full-screen viewer regression and verified correction

The live `9d110ca` viewer was reproduced with a controlled delay of `/assets/unit-imgOpenInterior2.webp` on `/residences/3402/`. After Next, its displayed image had `currentSrc: ""`, `complete: false`, and `naturalWidth: 0`, while its caption, alt and counter already described photo 2 / 3. The regression test failed at its assertion that pending navigation must retain the complete old frame.

`src/scripts/site.ts` now preloads and decodes a requested original, commits the image and its metadata together, ignores superseded responses, and invalidates an open request on viewer close. The cache has a three-entry limit and failed requests are evicted. Error guidance is separate from the actual photograph caption; the original image/counter stay intact on replacement failure. Requested navigation keeps its position so Next skips a failed image; Previous or reopening retries it. Initial failure exposes no broken image, and unavailable plan zoom stays disabled.

`src/components/Lightbox.astro` adds the existing palette's loading/error status and defers the empty viewer's image source. The existing image audit now skips image elements with no source and waits for real viewer readiness. No referenced image is exempted from its load assertion. `tests/e2e.mjs` accepts `PLAYWRIGHT_MODULE` so the suite can use the explicitly selected installed runtime.
